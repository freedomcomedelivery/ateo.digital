# Как получены эти данные

Коротко: замеры делает сеть собственных узлов внутри России, через реальные
абонентские подключения операторов. Подробная методика с оговорками —
на [странице методики](https://freedomchecker.ateo.digital/methodology/).

## Почему не из дата-центра

Фильтрация в российских сетях применяется **на уровне оператора**, а не страны.
Набор правил у МТС, МегаФона и регионального провайдера различается, а
дата-центр — это ещё один оператор, обычно с магистральным аплинком и совсем
другим режимом фильтрации, чем у абонента с телефоном.

Протокол, прекрасно живущий с арендованного сервера, может не подниматься с
мобильного интернета того же города. Поэтому замер идёт через абонентские
подключения.

## Как устроен замер

Узлы стоят в трёх регионах: европейская часть, Сибирь, Дальний Восток. На
каждом — проводное подключение и LTE-модем с несколькими профилями операторов
в eSIM; переключение между операторами программное.

Раз в цикл для каждого узла выпускаются задачи на **каждую комбинацию**
«оператор × сервис × цель». Внутри цикла задачи упорядочены по операторам:
модем держит одну сессию данных за раз.

Каденция — около **4 часов** на повторную проверку одной связки. Это измеренная
величина, а не настройка: медиана 4,57 часа, p90 — 6,03 часа.

## Что считать осторожно

- **Окно агрегации.** Поле `window_hours` говорит, за сколько часов собраны
  замеры в строке. Сравнивать строки с разным окном напрямую нельзя.
- **Отсутствие данных ≠ отказ.** Если связка не измерялась, строки не будет
  вовсе. Пустоту не следует считать нулём.
- **Отказ оператора ≠ блокировка.** Мобильный оператор может уронить сессию
  сам по себе; поэтому в строке есть `kind = direct` — базовая линия без
  туннеля.
- **Данные о сервисах — со слов сервисов.** Юрисдикция, цена и лимиты в
  каталоге не проверяются нами; проверяется только доступность.
